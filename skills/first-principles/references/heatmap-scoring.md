# ヒートマップの点数とデータの形（ステップ 3・4）

## 表の形

- **行**：要件。重みを付ける（必須＝3、重要＝2、あれば良い＝1）。
- **列**：資産の区分。既定は人・物・金・情報・時間・技術・関係の 7 つ。題材に合わせて減らしたり言い換えたりしてよい（例：学習なら「教材・時間・練習の場・教わる人・前提知識」）。8 列以上にしない。
- **マス**：その要件に対して、その区分の資産がどれだけ足りているか。

## 点数の基準

| 点 | 意味 | 判断の目安 |
|---|---|---|
| 3 | 足りる | 今のままで達成基準を満たせる |
| 2 | 少し足りない | 量か質が少し足りないが、やり方の工夫で埋まる |
| 1 | あるが使えない | 資産はあるが、量・質・時期・手の届き方のどれかが要件に合わない |
| 0 | ない | 資産がない、または手に入る見込みがない |
| — | 関係なし | その要件にその区分は効かない |

マスごとに根拠を 1 行書き、根拠の札（事実／申告／推測／慣習）を付ける。迷ったら低いほうの点を付け、根拠に「迷った理由」を書く。

## 優先度

```
優先度 = 重み × (3 − 点数)        # 0〜9。「関係なし」は計算しない
```

- 色は優先度で塗る（0＝白に近い、9＝濃い赤）。
- 要件ごとの「詰まり」は、関係ある列の中で一番低い点数。詰まりが 0〜1 の必須要件は、優先度に関係なく掘る候補に入れる。
- 掘る候補は優先度の上位 1〜3 マス。同点なら、ほかの要件にも効きそうな区分のマスを先にする。

## 会話だけのときの表

色の代わりに点数と記号を並べる。記号は優先度 7〜9 を ■■■、4〜6 を ■■、1〜3 を ■、0 を空欄にする。

項目の決まり：

- `cells[].score` は 0〜3 の整数か `null`（関係なし）。`cells` にないマスは「未評価」として灰色の斜線で表示される。
- `trees[].nodes[].stop` は `物理`・`外部`・`選択` のどれか。止めていない段は書かない。
- `tag` は `事実`・`申告`・`推測`・`慣習` のどれか。
- `summary` はページの先頭に出す結論の 3 項目（一番足りない所・遡って着いた前提・次にやること）。`detail`・`nextDetail` は補足の 1 行。書かなければ、優先度が一番高いマス、勧める案の外す前提、検証の確かめ方から自動で拾う。
- `trees[].nodes[].used` は、再構築案の材料にした枝（一番上の段）に `true` を付ける。その枝が赤い枠で囲まれる。
- `options[].drops` は、前提の台帳の `text` と同じ文にする。札が台帳から引かれる。勧める案には `recommended: true` を付ける（1 つだけ）。`raises` は上がるマスと点数（例：`時間 1 → 2`）。
- `experiment.onSuccess`・`onFailure` は、成功・失敗したときに次にすること。
- 書き終えたらブラウザで開き、表示が崩れていないこと（先頭に結論が出る、全マスに色か「—」が出る、マスを押すと根拠が出る、4 に枝ごとの木が出る）を確かめる。
